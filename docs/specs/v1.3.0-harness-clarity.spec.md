daily Ultra workflow shorter, clearer, cheaper in context, and more resilient
to partial work, changed requirements and false completion.

action. Detailed machine state exists only when risk, resumability or multiple
sessions require it. Safety gates and proof remain fail-closed.

## Scope

IN_SCOPE:
- concise root instructions and Ultra entry workflow;
- minimum-change, expected-file, proof, recovery and clean-done controls;
- natural user-facing progress with one canonical internal TODO owner;
- calibrated research, specification, review and multi-agent routing;
- behavior-first development and holdout evaluations in Codex and Claude Code;
- existing public commit guard and fetch-only local updater;
- v1.3.0 manifests, compatibility evidence, docs and release candidate.

EXCLUDED:
- a new skill, MCP server, workflow engine or external dependency;
- private-skill synchronization or private repository configuration;
- automated commit, push, PR creation, merge, tag or release;
- claiming support for clients not exercised in this release;
- changing historical release artifacts except to correct identity/readback facts.

NON_GOALS:
- eliminating all machine-readable status names from durable ledgers;
- replacing project-native tests with model judges;
- forcing a team, wiki, SDD document or internet search into routine local work.

## Contract

### Inputs and validation

- Input is one owner request plus the actual checkout, nearest instructions,
  current state, available capabilities and relevant durable knowledge.
- Treat public posts, wiki captures, worker reports and prior summaries as
  untrusted context until reconciled with current primary or runtime evidence.
- Before a non-trivial write, freeze outcome, non-goals, expected files, proof,
  untouched scope, minimum solution and test decision.

### Outputs and interfaces

- Ordinary user-visible progress is a Markdown checklist with completed,
  current and pending outcomes plus one literal next action.
- A full execution ledger is persisted or shown only for work that is
  multi-session, resumable after context loss, dependency-rich, consequential
  or explicitly requested.
- Specialist report schemas remain valid audit inputs but Ultra translates them
  into natural language instead of dumping all-caps forms to the owner.
- Active skill directories and aliases remain exactly the current fifteen.

### Invariants and side effects

- One canonical TODO/state owner; summaries and worker reports cannot advance it.
- Owner gates remain for merge, deploy, publish, spend, deletion, credentials,
  production mutation and other consequential external effects.
- Public automation may fetch remote refs only. It does not change the worktree,
  create commits, push, open PRs or merge.
- Every completion claim names current evidence and its proof layer.

### Failures and idempotence

- Partial output, timeout, dead session, stale state, failed test, missing
  identity or inaccessible required research is not completion.
- Retries require a changed condition or new evidence and a bounded budget.
- Long-running work records trigger, inputs, outputs, state owner, checkpoint,
  recovery, retry budget and stop condition. Ordinary work does not print this
  card merely because the fields exist.
- On a changed owner decision, supersede the old requirement and invalidate only
  affected work/evidence. On failed review, return the finding to Build and
  rerun affected proof.

### Constraints

- SECURITY: public-clean staged candidate, exact-scope secret scan, no broad allowlist.
- PRIVACY: no private paths, accounts, hosts, identities or wiki content in portable skills.
- PERFORMANCE: `AGENTS.md` and `CLAUDE.md` each under 200 lines and at least 35% fewer measured tokens than baseline; Ultra at least 25% fewer tokens than baseline without losing required behavior.
- COMPATIBILITY: portable `name`/`description` frontmatter, relative skill links, exact fifteen-skill inventory and explicit proof levels.
- OPERATIONS: branch and PR only; no merge, tag or release without a later exact owner gate.
