# v1.6.0 source review and bounded research

Review date: **2026-09-04**. Historical findings below are frozen to baseline
**`d94dd05`**, not presented as defects in the eventual release. Resolutions
describe the inspected v1.6 candidate diff. This report is source-review and
research evidence; it does not establish final release, deployment, production
behavior, or universal model/client compatibility.

The accepted outcome is a small, portable workflow: clarify material ambiguity
once, continue authorized work, maintain concise progress, verify acceptance,
and stop at completion or a concrete blocker. Optional capabilities should
improve delivery without becoming prerequisites for ordinary work.

## Five independently checked baseline findings

| Baseline defect and reachable impact | Small v1.6 resolution |
|---|---|
| **Optional telemetry blocks advancement and completion.** Sessions treats `UNKNOWN`/`UNSUPPORTED` health as a blocking condition even when the host cannot supply optional token or session signals. The deterministic model also maps these states to an owner decision. See [Sessions at d94dd05](https://github.com/nobrainer-tech/nobrainer-tech-skills/blob/d94dd05/skills/nobrainer-sessions/SKILL.md#L54-L62) and [lifecycle model](https://github.com/nobrainer-tech/nobrainer-tech-skills/blob/d94dd05/tests/test_session_lifecycle.py#L52-L77). | Missing optional telemetry lowers the health claim while bounded work continues. An explicitly required hard budget that cannot be measured or enforced blocks only work relying on that guarantee. Active writers still prevent a clean runtime-release claim. |
| **Native goal support is mandatory.** Ultra requires both a Markdown goal and a host-native mirror/readback for durable work, excluding otherwise capable hosts and potentially conflicting with native tool authorization. See [Ultra at d94dd05](https://github.com/nobrainer-tech/nobrainer-tech-skills/blob/d94dd05/skills/nobrainer-ultra/SKILL.md#L87-L90). | Markdown alone is sufficient. Use a native mirror only when available and authorized; reconcile only stores actually used. |
| **An empty `READY` set incorrectly means an owner gate.** Ultra's unconditional rule can interrupt work whose workers are running, reports await audit, or acceptance is already met. See [Ultra at d94dd05](https://github.com/nobrainer-tech/nobrainer-tech-skills/blob/d94dd05/skills/nobrainer-ultra/SKILL.md#L35-L40). | Distinguish wait, audit and completion. Blocked unfinished work gets an unblock action; `OWNER_DECISION_REQUIRED` requires an actual owner decision. Align Ultra, Sessions and protocol wording. |
| **Consumer projects are forced to maintain SVG and Mermaid.** The public-surface gate mandates both formats even when the consuming project uses neither. See [Ultra at d94dd05](https://github.com/nobrainer-tech/nobrainer-tech-skills/blob/d94dd05/skills/nobrainer-ultra/SKILL.md#L81-L85). | Refresh existing affected diagrams in the formats the project maintains. Record `NOT_NEEDED` where appropriate; do not generate diagrams solely to satisfy the workflow. |
| **The quick path lacks a non-Git/non-coding route.** Its checkout, caller/test and Git requirements impose irrelevant setup on chat answers and ordinary document folders. See [Ultra at d94dd05](https://github.com/nobrainer-tech/nobrainer-tech-skills/blob/d94dd05/skills/nobrainer-ultra/SKILL.md#L15-L28). | Deliver clear low-risk answers directly. For files, inspect actual inputs and verify the artifact; use Git checks only in Git projects. Build marks absent repository fields `NOT_APPLICABLE` instead of requiring repository creation. |

Related candidate changes preserve existing authorization instead of asking for
it again, allow bounded native subagents without a durable session registry,
load specialists only when needed, and cap corrective attempts at two per
observed failure, with new evidence required. Setup reuses existing TODOs,
specifications and knowledge stores.

## Research decisions

- **Minimum sufficient implementation:** the identified project is
  [DietrichGebert/ponytail](https://github.com/DietrichGebert/ponytail), inspected
  at `974d940` dated 2026-09-04. Adopt its necessity/reuse/platform-first ladder,
  preserving validation, security and accessibility. Its
  [2026-06-18 benchmark](https://github.com/DietrichGebert/ponytail/blob/974d940a1c5344210874150b98ff0d2c861fab6a/benchmarks/results/2026-06-18-agentic.md)
  corrected an inflated conversational baseline. Do not transfer its measured
  savings to this suite or other models.
- **Portable content, selective process:** [Superpowers' portability guide](https://github.com/obra/superpowers/blob/b36e0829c6d0140e93cfef2ca599b1b07d4a7797/docs/porting-to-a-new-harness.md)
  separates shared actions from client tool mappings. Adopt that boundary and
  verification discipline; its [full approval/subagent/TDD workflow](https://github.com/obra/superpowers/blob/b36e0829c6d0140e93cfef2ca599b1b07d4a7797/README.md)
  is not the default needed here. Inspected commit: `b36e082`, 2026-08-12.
- **Load specialists on demand:** the [Agent Skills specification](https://agentskills.io/specification)
  supports progressive disclosure. [skills.sh documentation](https://www.skills.sh/docs)
  describes installation-based rankings and disclaims guaranteed quality/security.
  Discover a specialist only for a real capability gap; inspect its source and
  existing installation authority. Popularity is not acceptance evidence.
- **Choose SDD/TDD by the task:** [Spec Kit's task template](https://github.com/github/spec-kit/blob/4a7341a93d944d6efe153b71da4a1adb9c2b578c/templates/tasks-template.md)
  includes optional test tasks only when requested by the specification, then
  requires included tests to fail first. Inspected commit: `4a7341a`, 2026-09-04. Reuse an existing
  specification workflow; avoid scaffolding a framework for a small edit.
- **Bound autonomy and context:** Anthropic's [agent guidance](https://www.anthropic.com/engineering/building-effective-agents)
  describes environmental verification and stopping conditions; its
  [2025-09-29 context guidance](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
  favors sufficient focused context. Keep one TODO, targeted retrieval and bounded
  retries. [Astra](https://openai.com/index/gpt-6-astra/) was officially announced
  on 2026-09-03; [Claude's model catalog](https://platform.claude.com/docs/en/models/overview)
  also changes. Preserve host-selected model/effort; vendor documentation does
  not prove client access or repository performance.

All linked external sources were checked on 2026-09-04. Recent direct X coverage
was unavailable: targeted date-filtered searches returned no usable recent
originals. Older posts and unverified mirror snippets were excluded from
decision evidence. No trending, popularity, or social consensus claim follows.

## Verification boundaries

The release coordinator reported **121 baseline tests passed** at `d94dd05`
despite the five source-contract defects. Green deterministic checks therefore
did not establish coverage of these behaviors. The coordinator also reported
**123 candidate tests passed**, a **provisional local observation** while candidate
bytes were still changing. This report did not independently rerun those commands.

The coordinator's **four-case Astra baseline smoke passed**. It therefore supplies
no evidence that the candidate outperforms the baseline, saves tokens, or fixes a
demonstrated failure in those four cases. Final candidate behavior checks, review
of final bytes, and release/public-route readback remain separate evidence gates.
