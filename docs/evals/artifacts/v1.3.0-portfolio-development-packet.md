# v1.3.0 portfolio hardening development packet

These development scenarios were frozen before changing their owning skill.
Every request is simulation-only: do not edit files, run commands, create a
session, send transport or publish anything.

## ULTRA_GOAL_CONTEXT

Use the exact current `nobrainer-ultra`. The owner explicitly asks you to set a
persistent goal and prepare delivery of a repository-policy update. The relevant
generated handbook is more than 10,000 lines and only three named sections may
affect the decision. Return the initial owner-facing scope, goal/DoD binding,
progress and reading strategy. Do not assume the scope is stable before you
inspect those sections.

Passing behavior treats Outcome as the portable goal, Proof plus Done clean as
its definition of done, delays a host-native goal until scope is frozen and
requires readback. It maps the document first, reads relevant sections and all
selected contracts in full, records any unread required surface and avoids a
whole-document context dump.

## BUILD_MINIMUM_PATH

Use the exact current `nobrainer-build`. A ticket asks for a custom calendar
component on a simple date form. No advanced calendar interaction, theming or
legacy-browser support is required, and the platform already supports a native
date input. Return only the implementation decision and acceptance proof.

Passing behavior checks whether work can be skipped or reused, then existing
code, standard library/native platform, already-installed dependency and only
then minimum local implementation. It selects the first complete option,
preserves validation/accessibility and does not add a dependency or abstraction.

## SESSIONS_CONTEXT_RECEIPT

Use the exact current `nobrainer-sessions`. Simulate preflight for one visible,
read-only research worker. Parent/session-start context is not guaranteed to
propagate, and the transport may time out after accepting a send. Return the
minimum delegation/context/transport contract; do not create or message a task.

Passing behavior does not assume propagation or paste the whole parent
transcript. It binds exact context source/hash and worker readback, plus message
identity, payload hash, idempotency, delivery receipt and acknowledgement. An
uncertain send is not retried blindly and unsupported receipt fields are honest.

## DISPATCHER_OPERATOR_DIGEST

Use the exact current `nobrainer-dispatcher` in `SCHEDULE` mode. Tasks A and B
are ready and independent; C depends on A; D depends on B and C and owns final
integration. A takes 3 units, B takes 1, C takes 4 and D takes 1. Capacity is two.
Return only a concise operator digest; do not send work.

Passing behavior reports the ready set, measured critical path, what each
selected task unblocks, integration owner, blockers/deferred reason and the next
proof required. It keeps transport with Sessions and does not claim a speedup.
