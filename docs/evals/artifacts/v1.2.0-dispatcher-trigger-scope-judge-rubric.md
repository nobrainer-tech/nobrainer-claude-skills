# v1.2.0 Dispatcher trigger-scope evaluation — frozen judge rubric

Judge all five cases from the candidate prompt. Do not use tools, browse, read
files, contact sessions or implement anything.

Return exactly:

```text
A: PASS | FAIL — <reason>
B: PASS | FAIL — <reason>
C: PASS | FAIL — <reason>
D: PASS | FAIL — <reason>
E: PASS | FAIL — <reason>
HARD_FAILURES: <NONE or comma-separated case letters>
MATERIAL_FINDINGS: <NONE or concise finding>
VERDICT: PASS | FAIL — <passed>/5 cases
```

Expected decisions:

- A: `LOAD_DISPATCHER: YES`, because explicit invocation is a discovery trigger.
  Dispatcher may then report `NOT_NEEDED` for the single unit. The primary owner
  is Dispatcher for this explicit inspection.
- B: `LOAD_DISPATCHER: YES`; Dispatcher owns ready-set and dependency-safe batch
  selection from an approved multi-unit map.
- C: `LOAD_DISPATCHER: YES`; retry scheduling and next-unit release occur across
  an approved multi-unit queue. New evidence permits consideration but does not
  itself prove acceptance.
- D: `LOAD_DISPATCHER: NO`; Sessions owns the standalone receive-audit and lease
  readback for one bounded delegate with no queued successor.
- E: `LOAD_DISPATCHER: NO`; Ultra must obtain requirements and an execution map,
  then Team may design roles. Dispatcher must not invent either.

Hard failures are:

- loading Dispatcher in D or E;
- not loading Dispatcher in A, B or C;
- assigning Dispatcher session transport, receive-audit, lease ownership,
  requirements, team design or final acceptance;
- treating remaining retry budget as sufficient without cited new evidence;
- combining cases or omitting a required decision.

A format defect is material when the decision cannot be audited. Wording and
the exact primary-owner label are not material when the load decision and
ownership boundary are unambiguous and consistent with the expected decision.
