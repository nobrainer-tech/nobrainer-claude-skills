  `READY` work becomes `STOPPED`; its dependants remain unreleased as `PENDING`

- Readiness may be recomputed only after rebuilding the affected path under a
  new plan fingerprint and rerunning every gate.
- If affected work is `SENT`, `CLAIMED` or `RUNNING`, stop further routing.
  Sessions alone requests and reads back a controlled stop. Never infer
  cancellation, lease release, non-execution or delivery to a replacement
  target.
- Dispatcher owns scheduler state. Sessions alone owns exact identity,
  transport, lease and `RECEIVE_AUDIT` evidence.
- `PENDING` and `BLOCKED` are both unreleased. A task can become `READY` only
  when every predecessor is `ACCEPTED` and every other readiness gate passes.
- `SENT` requires fresh transport readback for the exact target and message. A
  local command exit or API submission is not delivery.
- A correctable audited defect remains `CORRECTION_REQUIRED`. The assigned
  method repairs it, affected tests run, every required failed review repeats
  with fresh proof, and only then may a fresh post-repair `RECEIVE_AUDIT` make
  it eligible for `ACCEPTED`.

- On any problem, complication, ambiguity, difficulty or error, first query
  relevant wiki decisions and lessons, then perform current internet research
