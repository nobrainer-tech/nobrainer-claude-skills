## Complete relevant contract

- Dispatcher owns scheduler state. Sessions alone owns exact session identity,
  checkout/lease/active-turn preflight, prompt transport and transport readback.
  A submission or zero exit is not delivery. Dispatcher may record
  `READY -> SENT` only from exact fresh Sessions transport readback. `SENT`
  proves delivery only, never execution, lease ownership or completion.
- A worker performs one bounded work unit, never selects or dispatches a
  successor, releases its lease on finish or hard stop and sends one report.
  A worker's `FINISHED`, exit code or `NEXT_ACTION` is untrusted until Sessions
  performs a fresh independent `RECEIVE_AUDIT` bound to exact identity,
  checkout, diff, tests, review, runtime evidence, side effects and lease.
- Dependants remain unreleased as `PENDING` or `BLOCKED` until every predecessor
  is independently audited and `ACCEPTED`. Unknown/conflicting evidence, active
  work or lease conflict preserves state and stops routing.
- A changed owner decision supersedes the old requirement. Move affected
  not-started `READY` work to `STOPPED`, keep dependants unreleased, invalidate
  old plan/evidence, create a new plan fingerprint and recompute every readiness
  gate. If affected work is `SENT`, `CLAIMED` or `RUNNING`, stop new routing and
  use Sessions to request and read back a controlled stop; never infer
  cancellation, lease release, non-execution or deployment to another target.
- A failed review keeps the task `CORRECTION_REQUIRED` and invalidates affected
  proof. Route one bounded correction through the assigned implementation
  method. After repair, rerun affected tests and every required failed review,
  then run a fresh post-repair `RECEIVE_AUDIT` before `ACCEPTED`; none of these
  gates substitutes for another.
- Retries require both remaining retry budget and a cited new fact: new evidence
  or a changed condition that changes the blocker. The same blocker fingerprint
  without such a fact must not be retried. Preserve the prior evidence and
  state; a repeated unexplained defect routes to RCA. Never retry merely because
  the owner asks, a worker is idle, or the previous command exited zero.
- On any problem, ambiguity, complication, difficulty or error, query relevant
  wiki decisions and lessons, then perform current internet research and
  reconcile both with actual repository/runtime evidence. If required current
  research is unavailable, return `RESEARCH_BLOCKED`, choose no remedy and do
  not advance the scheduler from stale wiki, memory or an old workaround.
