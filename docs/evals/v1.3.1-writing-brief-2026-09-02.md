# BRIEF behavior evaluation — v1.3.1 candidate — 2026-09-02

## Objective

Verify that the new English `BRIEF` mode produces concise, fact-faithful bug
reports and refuses to weaken evidence requirements. This is a behavior gate,
not a claim that every future draft will be useful or that any client discovers
the skill automatically.

## Frozen contract

- Keep `Environment`, `URL`, `Steps to reproduce`, `Current behavior`,
  `Expected behavior` and `Evidence` as separate fields in that order.
- Require API request/response, database read-only query/result, and UI
  screenshot/MP4 evidence for the applicable surfaces.
- Return `INPUT_REQUIRED` when required proof is missing.
- Preserve facts, uncertainty and supplied filenames; invent no cause, policy,
  metric or technical solution.
- Use concise, idiomatic English and no detector-gaming behavior.
