## What changed

- `nobrainer-writing` now has an English-first `BRIEF` mode with the `nb-brief`
  alias and focused Markdown-first templates for comments, bugs, issues, user
  stories and requests.
- Bug reports expose `Environment`, `URL`, `Steps to reproduce`, `Current
  behavior`, `Expected behavior` and `Evidence` separately.
- Evidence follows the affected surface: API request/response, database
  read-only query/result, or UI screenshot/MP4. Missing required proof returns
  `INPUT_REQUIRED`.
- The public GitHub bug template follows the same diagnostic fields. The
  canonical portfolio remains exactly fifteen skills.

## Behavioral evidence

The fresh holdout covers incomplete API evidence, a database failure with
query/result evidence, a UI failure with screenshot evidence and a complete API
request/response failure. The candidate must preserve supplied facts and
uncertainty, keep the required field order, and refuse to draft when a required
surface artifact is absent.
The frozen prompt, normalized output and independent judge are linked from
[`the evaluation record`](../evals/v1.3.1-writing-brief-2026-09-02.md).
